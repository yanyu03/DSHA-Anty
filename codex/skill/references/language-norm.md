# L9 语言规范锁 · 表述策略 v2（有条件许可）

> **v1 → v2 的根本变化**：从「**禁用词表**」升级为「**有条件许可**」——
> **不再一刀切禁掉某些说法，而是要求：你要这么说，就必须在邻近窗口里给出补偿信息**（证据 / 范围限定 / 量化 / 对照 / 前提）。
> **规则更严**：新增 6 条窗口规则（L9.8–L9.13），并把 L2 从"全文档有样本即可"升级为"证据必须出现在断言附近"；strict 模式下有 8 类会直接拒绝。

---

## 一、为什么要改：当日记录审计（2026-10-06）

对**当日聊天记录**做词频审计（含我自己写的 5.4 万字符），得到设计依据：

| 越界类型 | 我（DSH 侧）每万字 | Anty 每万字 | 结论 |
|---|---:|---:|---|
| **验证类**（验证/证明/确认） | **12.5** | 1.2 | 最高频 → 不能禁，只能要求"证据要靠近" |
| **绝对量词**（全部/所有/任何/唯一） | **9.0** | 3.1 | 高频 → 要求范围限定 |
| 因果连词（因为/导致/使得） | 7.2 | 1.7 | 这份工程翻车最多处 → 要求对照或机制 |
| 绝对化（彻底/完美/绝对） | 5.3 | **4.0** | 已是硬锁（L9.1） |
| 程度无量化（大幅/严重/剧烈） | 3.3 | 2.5 | 要求配单位/数字 |
| 完成态（已修复/已生效） | 1.8 | 0.3 | 要求配验证标记（L9.4） |
| 时间绝对（永久/一劳永逸） | 1.5 | 0.2 | 要求前提（L9.12） |
| 断言强度（铁证/毫无疑问） | 0.4 | 0.1 | 硬锁（L9.11） |

> **关键发现**：如果按"禁用词"思路做，会同时禁掉我自己 12.5/万字的"验证"和 9.0/万字的"全部"——那是把正常表述一起杀掉。
> **所以 v2 的答案是：不禁，但要补偿。**

## 二、策略模型：触发 → 补偿 → 判定

```
发现触发词 ──► 在 ±W 字窗口内找补偿信息
                 ├─ 找到  → 放过（这是"有条件许可"）
                 └─ 没找到 → 按严重度报出
                              ├─ hard        : strict 模式直接拒绝
                              └─ strict_hard : advisory 只提醒；strict 拒绝
```

| 严重度 | 含义 | 当前规则 |
|---|---|---|
| `hard` | 无补偿可能，本身即越界 | **L5** 报告头缺失、**L6** 措辞、**L9.1** 禁用词、**L9.11** 断言强度 |
| `strict_hard` | 提醒；strict 下升级为拒绝 | **L2** 样本邻近、**L9.8** 绝对量词、**L9.9** 因果、**L9.12** 时间绝对 |
| `warn` | 始终只提醒 | L1 出处、L9.2 无据权威、L9.3 伪精度、L9.4 假完成、L9.5 术语漂移、L9.6 引用、L9.7 未来态、**L9.10** 程度、**L9.13** 自指 |

## 三、八条硬锁（strict 下拒绝）

| ID | 锁 | 拒绝条件 |
|---|---|---|
| **L5** | 报告头锁 | 写入 `documents_md/**` 或文件名含"报告/report" 的 `.md`，缺 6 字段（日期/设备/工具/样本/实测/结论） |
| **L6** | 措辞锁 | 命中 `ban_absolute` 子集 |
| **L9.1** | 禁用词锁 | 命中 `ban_absolute` / `ban_marketing` / `ban_promise` / `ban_selfpraise` |
| **L9.11** | 断言强度锁 | 毫无疑问 / 毋庸置疑 / 铁证 / 确凿 / 板上钉钉 / 必然如此 |
| **L2** | 样本邻近锁 | "验证/证明/确认/成立/已解决" ±120 字内无样本或复测证据 |
| **L9.8** | 绝对量词锁 | 全部/所有/任何/唯一/首个/一律 ±40 字内无范围限定 |
| **L9.9** | 因果声明锁 | 因为/导致/使得/造成/从而 ±60 字内无对照或机制 |
| **L9.12** | 时间绝对锁 | 永久解决/永不复发/一劳永逸 ±24 字内无前提（若/前提/除非/假设） |

## 四、六条提醒（含"有条件许可"示例）

| ID | 规则 | 触发 | 需要什么补偿 | 放过的例子 |
|---|---|---|---|---|
| L9.2 | 无据权威 | 官方/业内/权威/众所周知 | 任意来源标记 | "业内公认…**依据 0928 报告与 dumpsys 数据**" |
| L9.3 | 伪精度 | `xx.xx%` 或"提升/占比+两位小数" | 样本/误差/精度说明 | "**n=3 次实测**，提升 21.5%" |
| L9.4 | 假完成 | 已修复/已解决/已生效/收工 | 验证/复测/待验证 | "已修复，**待复测**" |
| L9.5 | 术语漂移 | 同组两种写法 | 统一用词 | 全文统一"待验证" |
| L9.6 | 引用不可解析 | `file:///…` 路径不存在 | 让路径真实存在 | 引用真实文件 |
| L9.7 | 未来态无标记 | 将/计划/预计 | 计划/待验证字样 | "**计划**重构（尚未开始，待验证）" |
| L9.10 | 程度无量化 | 大幅/严重/剧烈/飙升 | 单位或数字 | "大幅提升（**21.5%**）、发热改善（**-3.2℃**）" |
| L9.13 | 自指权威 | 我认为/我判断/我的结论 | 紧跟依据 | "我认为…**因为 n=3 次复测**" |

## 五、当日实测效果（v2 策略）

| 语料 | 字符 | 命中 | 分布特征 |
|---|---:|---:|---|
| **我今日输出** | 54,767 | **8 条** | 8 条分属 8 条不同规则 → 可逐句修改 |
| **Anty 今日导出** | 440,672 | **7 条** | 含 L9.11 断言强度（硬锁） |

> **v1 的对比**：v1 在 Anty 侧产物上给出 45 条命中、多为同类禁用词重复；
> **v2 按规则聚合**，同一规则每文档只报一次 —— 这就是"更灵活"的实际含义：**从"词墙"变成"逐条可执行的修改清单"**。

## 六、怎么改（不需要动代码）

编辑 `lexicon.json`：

| 想做什么 | 改哪里 |
|---|---|
| 某个词不该禁 | 从 `ban_*` 删除该词 |
| 新增禁用词 | 加入对应 `ban_*` |
| 新增一条"有条件许可" | 往 `window_rules` 加一条：`id / name / window / trigger / requires / strict_level` |
| 让某条更严 | 把它的 `strict_level` 改成 `strict_hard`，或把 `window` 调小 |
| 让某条更松 | 把 `window` 调大，或往 `requires` 里增加可接受的补偿词 |
| 调整断言邻近距离 | 改 `claim_proximity.window` |
| 调整术语一致性组 | 改 `term_groups` |

**改完立即生效**（校验器每次运行都重读词表），无需重装、无需重启。
