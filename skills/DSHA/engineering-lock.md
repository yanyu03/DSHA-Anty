# 工程锁（Engineering Lock）· 规格

> **它是什么**：把「工程不变量」从口号变成 Anty 每次必须过的闸门。
> **为什么需要**：这份工程的失败模式不是"做得少"，而是**做得多、但结论被自己的乐观放大**——`override-status 被宣布为执行器`、`89% 有效率`、`standby 桶生效`、`推算与实测混放`，全部是同一类问题：**AI 的措辞强度 > 证据强度**。
> **设计原则**：**默认只提醒、不阻拦**（advisory）；只有"报告缺头字段"和"绝对化措辞"两条在严格模式下才拒绝。锁的目的是造摩擦，不是把工作流锁死。

---

## 一、八把锁（每把都对应他的一个已发生过的翻车）

| # | 锁名 | 规则 | 对应翻车 | 执行层级 |
|---:|---|---|---|---|
| **L1** | **出处锁** | 任何数字/结论必须带来源（命令、文件、轮次、时间戳之一）；推算值必须标 `[EXTRAPOLATED]` | 4.10/4.20/4.30V 三档从未实测，却与实测并列 | 机械（提醒）+ 规范 |
| **L2** | **样本锁** | 出现"验证/证明/确认/成立"时，必须给出样本量；**n=1 只能写"单次观测"** | `override-status` 三次顺序测量即下结论 | 机械（提醒） |
| **L3** | **撤回锁** | 新结论若与历史结论冲突，必须在文中写下"**撤回：<旧结论>（时间/轮次）**" | 5 次撤回全靠记忆，没进流程 | 机械（话题表命中即提醒） |
| **L4** | **三件套锁** | 任务收尾必须交：**①报告 ②复现命令 ③回滚方式** | 大量脚本"跑过一次就没了"，无法复现 | 规范（注入） |
| **L5** | **报告头锁** | 报告必须含 6 个字段：日期 / 设备与固件 / 工具与版本 / 样本数 / 是否实测 / 结论强度 | 报告之间口径不一（7620 vs 6762mAh） | 机械（严格模式可拒） |
| **L6** | **措辞锁** | 禁用：史诗级 / 完美 / 100% / 彻底 / 万能 / 秒杀 / 绝对 / 史上最强 | Anty 反复输出"史诗级突破""100% 攻克" | 机械（严格模式可拒） |
| **L7** | **断拍锁** | 会话恢复（断拍 > 6h 或新会话接手）时，**先输出状态对账清单**：上次结论 / 未闭环项 / 可回滚点，才允许动手 | 他本人已有此习惯，但没写进流程 | 规范（注入） |
| **L8** | **外部审查锁** | 任何对外内容发布前，必须列 **3 个最可能被推翻的点** | 无同行审查，撤回永远是事后的 | 规范（注入 + 模板） |

## 二、执行层级说明

| 层级 | 落点 | 行为 |
|---|---|---|
| **规范（注入）** | `plugins/dsh-permissions/rules/AGENTS.md`（进入 agent 提示词） | Anty 每次都会读到，属于"纪律" |
| **机械（钩子）** | `plugins/dsh-permissions/scripts/englock.py` + `hooks.json` 的 PreToolUse 第二条 | 对写类工具做**确定性检查**，默认 `allow + reason`（提醒） |
| **人工（CLI）** | `englock.py check <file>` / `status` | 随时自查，也可进 CI/提交前钩子 |

**默认安全**：`englock.json` 里 `mode: "advisory"`；任何内部异常一律**放行**（fail-open），绝不因为锁自己出错而卡住工作流。

---

## 三、严格模式（可选）

把 `plugins/dsh-permissions/englock.json` 的 `mode` 改为 `"strict"`，以下两种情形会返回 `deny`：

1. 写入**报告类**文件（目标路径含 `documents_md/` 或文件名含 `报告|report`）却**缺少任一报告头字段**；
2. 内容包含**绝对化措辞**（L6 词表）。

其余四把锁在严格模式下仍只是提醒。

---

## 四、与既有插件的关系

| 组件 | 角色 |
|---|---|
| `dsh-permissions`（plugin name = **DSHA**） | 管**权限档位**（read-only / workspace-write / danger-full-access / auto）——"能不能做" |
| **工程锁 englock** | 管**工程纪律**（出处/样本/撤回/措辞…）——"做得对不对" |

两者是**正交**的：权限锁防越权，工程锁防自欺。可以单独启用任一个。

## 五、他为什么需要这套锁（对症）

| 他的习惯 | 带来的风险 | 哪把锁对冲 |
|---|---|---|
| 爆发式推进（单日 40 问） | 结论密度 > 验证密度 | L1 L2 L5 |
| 单人闭环、AI 既执行又反馈 | 措辞强度被 AI 抬高 | L6 L8 |
| 断拍 57h 后仍能接上 | 靠记忆接续会带回旧错误 | L3 L7 |
| 索引式知识（先要结果后补原理） | 推算被当成实测 | L1 L5 |
| 产出极多但没有回滚习惯 | 改完不知道退路 | L4 |
