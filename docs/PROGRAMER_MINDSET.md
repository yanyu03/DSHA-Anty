# Programer 工程实践规范

Programer是本维护分支的工程审查模块名称，不指代个人、课程或第三方认证。本文采用通用工程概念，不包含课程笔记或个人表达风格模仿。

## 工程要求

- 明确对象、输入、提交、环境和授权范围。可读源码使用仓库工具；明确的二进制或运行时问题才调用REA。
- 参数优先于环境变量，再使用已声明默认值。显式无效覆盖拒绝执行，不静默更换解释器、权限来源或账号。
- 副作用前校验类型、范围和目标身份。错误摘要不回显凭据、宿主目录和完整私有配置。
- 明确文件、锁和子进程的所有权及收尾路径，用上下文或finally管理生命周期。记录清理失败，不能用退出码代替确认。
- 未知规模输入采用有界读取或流式处理。共享可变状态应说明同步方式；并发选择应有实际收益依据。
- 外部命令采用有界等待。超时不证明外部操作停止；观察原句柄后再决定重试。
- 验证用户可观察行为及关键失败路径，记录样本、命令、退出状态和证据。未执行写NOT_RUN，局部通过不推论整个产品完成。

## 交付

说明改动、实际验证、限制和回滚方式。按任务要求提交相关已验证内容，核对远程提交与工作区。私有日志、凭据和未明确可公开的参考资料不进入公开分支。

本模块不改变Codex权限、冻结任务书或用户授权，也不构成正确性或版权状态保证。设计与来源边界见docs/PROGRAMER_DESIGN.md及docs/PROGRAMER_PROVENANCE.md。
