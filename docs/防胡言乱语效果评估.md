> **评估日期**：2026-10-06　**语料**：日期归档报告 43 份 + Anty 侧产物 28 份（1,300 万字符）+ DSH 侧文稿 36 份

## 二、两次针对性改进（都是被真实语料逼出来的）

### 改进 1｜引用掩码：**"引用别人的话"不算自己说**

**问题**：我的专题文稿大量**引用 Anty 的原话**（含"史诗级""100% 彻底"），纯文本扫描器分不清"引用"与"自述"，导致我自己的文稿被误判。

**修法**：新增 `mask_quoted()` —— 计分前先剔除 ①代码围栏 ②引用块（`>` 开头行）③`【原文】…` 标注段。

**验证**：
| 用例 | 期望 | 实测 |
|---|---|---|
| `> 【原文】这是史诗级突破，100% 彻底解决` | 不报 | ✅ 空 |
| `这是史诗级突破，100% 彻底解决，已验证有效。` | 报 | ✅ 命中 L9.1 + L2 |
| 引用 + 自述混排 | 只报自述 | ✅ 只报自述那一句 |

**效果**：DSH 侧文稿 L9 命中 **49 → 46**，命中文档占比 **89% → 83%**。

### 改进 2｜L9.3 收窄：**实测小数 ≠ 伪精度**

**问题**：抽检发现它把 `3.67W`、`639.02MB`、`3.409GHz` 这类**仪器读数**当成"伪精度"报错——这些数字恰恰是可信的。

**修法**：只在**精度主张**上触发 —— `\d+\.\d{2,}\s*%`，或"提升/降低/准确率/占比/优化到"后紧跟两位以上小数。**不再**对任何两位小数开火。

**效果**：L9 命中三组分别 **45 → 37 / 62 → 52 / 46 → 41**。

## 四、结论：这套锁的实际效果

| 维度 | 结论 |
|---|---|
| **对"胡言乱语"的抓取** | **有效**。硬锁 L9.1 能准确抓住绝对化/营销腔/承诺语/自夸这四类"措辞强度超出证据强度"的表达——拿 Anty 自己的《深度画像与专属点评》当靶子，一击即中 |
| **对"陈旧结论"的抓取** | **超出预期**。L3 能在报告里认出"已被撤回的话题却没有撤回标注"，这是人最容易漏的 |
| **对"缺证据"的抓取** | 有效但**偏严**：L1/L2/L5 会让几乎每份技术文档都中招（多数报告确实没有标准报告头、也常省略样本量） |
| **定位** | **提醒型扫描器**（high recall / low precision），适合"发布前过一遍"，**不适合当 CI 门禁**；真要做门禁，只用 **L9.1 + L5** 两条硬锁 |
| **已知误差类型** | ①行内引号引用（`"史诗级"` 无 `>` 或 `【原文】` 标记）仍会被算作自述　②实测小数若出现在"提升/占比"句式里仍会报 L9.3 |
| **调校方式** | **改 `lexicon.json` 词表即可**，无需改代码、无需重装；误报某词删该词，漏报某词加该词 |

---

## 五、一句话

> **它不能阻止模型胡说，但它能让"胡说"在发布前被点名。**
> 在这套语料上：Anty 侧 **82%** 的文档被点出问题，其中"史诗级/彻底/绝对"这类硬伤被 **100% 抓住**；它自己的误报率约 **17%**，且集中在"实测小数"与"行内引用"两类——这两类已通过掩码与收窄削减，剩余部分建议**人工复核而非继续改锁**（避免把锁调成只会点头）。

# 附录 · v2 策略（有条件许可）在当日记录上的实测（2026-10-06）

## 一、当日记录词频审计（规则设计依据，含 DSH 侧自我审计）

| 越界类型 | 我（DSH 侧）每万字 | Anty 每万字 | 处置 |
|---|---:|---:|---|
| 验证类（验证/证明/确认） | **12.5** | 1.2 | 不禁止 → **L2 改为"证据须在 ±120 字内"** |
| 绝对量词（全部/所有/任何/唯一） | **9.0** | 3.1 | 不禁止 → **L9.8 要求 ±40 字内范围限定** |
| 因果连词（因为/导致/使得） | 7.2 | 1.7 | 不禁止 → **L9.9 要求 ±60 字内对照或机制** |
| 绝对化（彻底/完美/绝对） | 5.3 | 4.0 | 硬锁 **L9.1** |
| 程度无量化（大幅/严重/剧烈） | 3.3 | 2.5 | **L9.10 要求配单位或数字** |
| 完成态（已修复/已生效） | 1.8 | 0.3 | **L9.4 要求配验证标记** |
| 时间绝对（永久/一劳永逸） | 1.5 | 0.2 | **L9.12 要求前提** |
| 断言强度（铁证/毫无疑问） | 0.4 | 0.1 | 硬锁 **L9.11** |

> **设计结论**：若按"禁用词"思路处理，会同时禁掉我自己 12.5/万字的"验证"与 9.0/万字的"全部"——等于把正常技术表述一起杀掉。
> **所以 v2 改为"有条件许可"**：允许说，但必须在邻近窗口给出补偿信息。

## 二、v2 策略在当日语料上的结果

| 语料 | 字符 | 命中 | 分布特征 |
|---|---:|---:|---|
| **DSH 侧今日输出** | 54,767 | **8 条** | 分属 8 条不同规则（可逐句修改） |
| **Anty 今日导出（1003 三份）** | 440,672 | **7 条** | 含 **L9.11 断言强度（硬锁）** |

**新规则在当日语料中实际抓到**：L9.8 绝对量词 · L9.9 因果声明 · L9.10 程度无量化 · L9.11 断言强度 · L9.12 时间绝对 · L9.13 自指权威 —— 六条全部有真实命中，不是纸面规则。

## 四、本轮修复的真实缺陷

| 缺陷 | 后果 | 修法 |
|---|---|---|
| `mask_quoted()` 缺失 | 引用他人的话被算作自述（我自己的文稿被误伤） | 代码围栏 / 引用块 / `【原文】` 段不计分 |
| L9.3 过宽 | 把 `3.67W`、`639.02MB` 当伪精度 | 收窄为只对"精度主张"触发 |
| 自检用例把「逸」写成 `\u900d`（应为 `\u9038`） | L9.12 用例永不触发，规则形同未测 | 修正码点；30/30 全绿 |
| `verify.ps1` 写死「19/19」 | 升级后体检误报失败 | 改为通用 `N/M` 判定（N==M 即通过） |
